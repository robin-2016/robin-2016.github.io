Kiri 两周近 9000 星，要替掉 Docker Desktop

走 Docker API 起停一个容器，只要 2.55 毫秒。

摘要

Kiri 是一个用 Rust 写的轻量容器运行时，支持 macOS、Windows、Linux，兼容 docker 命令、Compose 和 buildx。仓库 11 月初才创建，两周就逼近 9000 星。

它是什么

很多人装 Docker Desktop，只是为了在本机跑几个容器。结果是一个常驻后台、占内存、启动慢的大家伙。

Kiri 想做的是它的轻量替身：Rust 编写，开源协议 Apache-2.0，自带一个原生窗口，同时说 Docker Engine API，所以你手里的 docker、Compose、buildx 基本不用换。

名字来自伊博语 ntakịrị，意思是“小”。

关于热度：仓库创建于 2026 年 11 月 2 日，截至写稿时星标约 8960，最新版本是 v0.2.1。它还很年轻，下面的结论都要带着这一点看。

核心优势

快。 项目自己的基准测试里，alpine 跑一次 true 再删除，取 30 次中位数：

Docker Engine API docker 命令行
Kiri 2.55 ms 14.2 ms
Docker Desktop 213 ms 243 ms
OrbStack 380 ms 442 ms

走 API 大约快 80 倍，走命令行大约快 17 倍。注意这是项目方自测的数据，方法和全部结果在仓库的 bench/results.json 里，也可以自己用 kiri bench 复跑。

省。 虚拟机空闲 60 秒就自动休眠，守护进程常驻内存约 15 MB，唤醒约 0.15 秒。

简。 架构里没有 runc、没有 shim、也没有 dockerd。虚拟机用一个定制的 10 MB 内核，PID 1 是一个约 900 KB 的 Rust 代理，用一次 clone3 直接把容器放进命名空间和 cgroup。

兼容。 docker、Compose、buildx、docker login 都能用；Apple 芯片的 Mac 上，amd64 镜像通过 Rosetta 运行。

还送不少东西：

  • 本地域名：<名字>.kiri.local，HTTPS 由 Kiri 自己的证书机构签发
  • 一条命令起单节点 Kubernetes
  • 一条命令建 Linux 机器
  • 原生窗口加菜单栏图标，界面支持 38 种语言

面向人群

  • 在 Windows 上只想跑容器、不想装 Docker Desktop 的开发者
  • 用 Mac，觉得 Docker Desktop 太吃资源的人
  • 想在本机快速起 Kubernetes 或 Linux 环境的人
  • 对 Rust 实现的容器运行时好奇的人

关于 Windows，说清楚一件事

Windows 版本支持 Windows 10 和 11（x86-64 和 Arm），但它是通过 WSL 2 运行的。也就是说，它省掉的是 Docker Desktop 这个应用，而不是 WSL 2 本身，你的机器上仍然需要启用 WSL 2。

安装包是 .msi，装好后会提供一个叫 kiri 的 Docker context，通过命名管道和 WSL 里的 Kiri 通信，不需要改 WSL 或 Windows 的网络设置。

快速上手

macOS 14+ 装 .dmg，Windows 装 .msi，Linux 装 .deb 或 .rpm。第一次打开 Kiri，它会自动建好 kiri 这个 Docker context，之后用起来是这样：

# 用熟悉的 docker 命令，指定 kiri 这个 context
docker --context kiri run --rm alpine echo hello
docker --context kiri compose up -d

# 一条命令起单节点 Kubernetes（k3s），kubectl 上下文名就叫 kiri
kiri k8s start

# 建一个 Ubuntu 机器并进入
kiri machine create dev --distro ubuntu && kiri machine shell dev

# 从 OrbStack 或 Docker Desktop 迁移镜像、卷和容器
kiri import

Docker 的命令也可以直接写成 kiri 命令，比如 kiri run、kiri ps、kiri compose up，并且始终指向 Kiri 自己。

进阶用法

本地域名。 首次打开应用时会询问是否启用，也可以在设置里的“域名”页开关。启用后，Compose 服务可以用 <服务>.<项目>.kiri.local 访问；给容器加上 dev.kiri.domain=api.myapp 标签，可以自定义它的域名。不想配置的话，<名字>.kiri.localhost 开箱即用。

USB 设备（测试版）。 串口适配器、Zigbee 棒、开发板这类设备，可以直接交给容器使用，Mac、Windows、Linux 都支持。

搬家。 kiri import 会把 OrbStack 或 Docker Desktop 里的镜像、卷和容器带过来，迁移成本不高。

目前要注意的坑

  • 项目很新，v0.2.1 就是现在的最新版，生产环境先别急着换。
  • 构建时 --add-host name:host-gateway 配合 BuildKit 会报错，因为 Kiri 的构建器是 docker-container 驱动。临时办法是直接写网关地址，或者设 DOCKER_BUILDKIT=0。项目路线图里的下一步，就是做一个内置构建器来解决它。
  • Mac 睡眠时，已挂载的 USB 设备会暂时从容器里消失，唤醒后会自动重新接上。

速记清单

适合收藏，下次想换掉 Docker Desktop 时对照：

  1. 先确认系统：macOS 14+、Windows 10/11（需要 WSL 2）或 Linux
  2. 装好后用 docker --context kiri run --rm alpine echo hello 验证
  3. 老环境用 kiri import 迁移，再用 kiri bench 自己验证速度
  4. 构建用到 host-gateway 的项目，先看上面的临时办法
