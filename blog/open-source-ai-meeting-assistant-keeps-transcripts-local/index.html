隐私开源工具

开源AI会议助手让转录数据不出本地

摘要

Meetily 是一款完全在本地运行的开源 AI 会议助手：实时转录、生成摘要全部在自己的电脑上完成，不需要把录音和文字稿传到任何服务器。项目用 Rust 打底，前端基于 Tauri + Next.js，转录引擎支持 Whisper 和 Parakeet 两种模型，摘要生成默认接入本地的 Ollama，也可以按需切换到 Claude、Groq、OpenRouter 或任意兼容 OpenAI 接口的服务。

是什么

会议纪要类工具的痛点很直接：录音和转写内容往往要经过云端服务商，企业和专业人士的敏感对话就这样留在了别人的服务器上。Meetily 想解决的正是这个问题——从麦克风采集音频，到语音转文字，再到用大模型生成摘要，整条链路都可以完全离线跑在本地设备上，中间不产生任何网络请求。

这类隐私风险并不是危言耸听：IBM《2024年数据泄露成本报告》显示，当年数据泄露的平均损失已经涨到 488 万美元；GDPR 罚款自 2018 年生效以来的累计金额，到 2026 年已经突破 71 亿欧元。围绕 AI 会议记录工具的诉讼也已经出现——针对 Otter.ai 的多起集体诉讼在 2025 年被合并审理，指控其在未经全员同意的情况下录音并用于模型训练；类似的诉讼也发生在 Fireflies.ai 身上。这些都是真实发生、仍在推进中的案例，而不是遥远的假设风险。

核心优势

  • 本地优先：转录模型、录音文件、文字稿全部存在本机磁盘上，处理过程不经过任何云端接口。
  • 实时转录 + 双模型可选：内置 Whisper 和 Parakeet 两套语音识别引擎，可以按语言和场景切换。
  • 摘要供应商可插拔：默认用本地的 Ollama，也可以在设置里换成 Claude、Groq、OpenRouter，或者接入企业自建的 OpenAI 兼容端点。
  • 专业级音频采集：可以同时采集麦克风和系统声音两路输入，内置自动闪避（ducking）和防削波处理，避免会议录音里人声被系统提示音盖掉。
  • 导入与增强（Beta）：支持导入已有的录音文件重新生成转写，或者用另一套模型/语言重新跑一遍已录制的会议，方便对比效果。
  • GPU 加速开箱即用：macOS 上用 Apple Silicon 的 Metal + CoreML，Windows/Linux 上分别支持 NVIDIA CUDA 和 AMD/Intel Vulkan，构建时自动启用，不需要手动配置。
  • 跨平台 + 完全开源：支持 macOS、Windows、Linux，MIT 协议开源，Community 版本承诺永久免费。

面向人群

  • 处理敏感信息、不希望会议记录流向第三方云服务的企业和团队（法务、医疗、咨询、涉密行业等）
  • 已经在用本地大模型（如 Ollama）、希望把会议转录和摘要也纳入自托管体系的开发者
  • 需要跨平台会议记录方案、又不想为每个坐席支付云端订阅费用的中小团队
  • 对开源项目感兴趣、愿意参与共建功能的社区贡献者

如何使用

macOS：

  1. 从 Releases 页面下载最新的 meetily_x.x.x_aarch64.dmg
  2. 打开下载的 .dmg 文件
  3. 把 Meetily 拖到「应用程序」文件夹
  4. 从「应用程序」文件夹启动 Meetily

Windows：

  1. 从 Releases 下载最新的 x64-setup.exe
  2. 运行安装程序

Linux（需要从源码构建）：

git clone https://github.com/Zackriya-Solutions/meeting-minutes
cd meeting-minutes/frontend
pnpm install
./build-gpu.sh

安装完成后，在设置里选择转录模型（Whisper 或 Parakeet）和摘要供应商（默认 Ollama，也可以切换到 Claude / Groq / OpenRouter / 自定义 OpenAI 兼容端点），就可以开始录制并实时查看转写和摘要了。项目还提供了 Community 版本之外的 Meetily PRO，面向需要更高转录精度、自定义摘要模板、批量导出以及自托管团队部署的用户，但 Community 版本的本地转录、AI 摘要等核心能力会一直保持免费开源。

如果想参与开发，项目需要 Rust 和 Node.js 环境，具体构建步骤可以参考仓库里的 Building from Source 指南。
